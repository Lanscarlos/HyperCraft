# HyperCraft 文件管理重构 v2 · VS Code 式布局

**本文取代 v1（`2026-09-14-file-manager-rework-design.md`）。** 如果 v1 已经部分落地，先看 §1 的迁移说明，不要把两份混着执行。

仍然不动配色主题与字体——文中的"强调色 / 警告色 / 危险色"一律复用项目现有 token。

---

## 1. 与 v1 的关系

v1 的结论是"三栏：目录树 + 文件列表 + 编辑器"。实测下来这个结构在分屏对照时宽度不够，而且左栏被切成上下两半后两边都不好用。v2 改为参照 VS Code 的三层结构。

### v1 中**作废**的条目

| v1 章节 | 作废原因 |
|---|---|
| §3 布局规格（三栏） | 改为"活动栏 + 侧边栏 + 主区"两栏结构，见 §3 |
| §5 目录树"只显示文件夹" | 改为带文件的单一树，见 §5 |
| §6 文件列表作为独立常驻栏 | 取消。列表职责移交主区，见 §6 |
| §6.1 紧凑/详情切换 | 取消。主区宽度充足，不再需要密度切换 |

### v1 中**继续有效**、原样保留的条目

这些如果已经做完了就别动：

- §4 面包屑：可点击分段、点击空白转为路径输入框、中间省略
- §6.2 行规格：文件夹在前、按类型着色的图标、**7 天内相对时间**
- §6.3 行操作 hover 才出现、删除收进 `⋯`、文件夹删除需输入名称
- §6.4 多选与批量操作条（复选框**原地替换**类型图标，不新增列）
- §6.5 空状态 / 搜索无结果 / 读取失败 / 拖拽上传
- §7.2 改动行标记（行号槽 + 正文左侧竖条 + 还原此行）
- §7.4 保存与冲突、外部变更提示、运行中保存配置提示重启
- §7.5 大文件与二进制文件处理
- §9 后端确认清单（另见本文 §11，新增一项）

### v2 新增

- 一级导航变成常驻图标栏（**影响全部页面**，见 §2 的分期建议）
- 侧边栏 `⌘B` 折叠
- 主区双形态：浏览态 = 目录详情列表，编辑态 = 编辑器
- 左右 / 上下分屏
- `⌘P` 转到文件

## 2. 分两个 PR 做

§3 的一级导航图标栏会改到**每一个页面**的外壳，blast radius 远大于文件页本身。建议拆开：

- **PR 1 — 全局外壳**：只做 §3。所有页面沿用现有内容，只是外面那层导航换成图标栏。这一步应该是纯视觉改动，不碰任何页面逻辑。
- **PR 2 — 文件页**：§4 到 §10。

PR 1 单独合并、单独回归，出问题好定位。

## 3. 一级导航：常驻图标栏

### 3.1 结构

```
┌──────┬─────────────────────────────────────────────┐
│      │  全局顶栏 48px（实例切换 / 状态 / 启停 / ⌘P）  │
│ 图标 ├─────────────────────────────────────────────┤
│ 栏   │                                             │
│ 56px │              页面内容区                       │
│      │                                             │
│      ├─────────────────────────────────────────────┤
│      │  全局状态条 26px                             │
└──────┴─────────────────────────────────────────────┘
```

全局顶栏和状态条横跨整宽，图标栏在它们之间的左侧——**顺序以实现方便为准，但三者在所有页面必须完全一致。**

### 3.2 图标栏规格

- 宽 **56px**，背景同卡片色，右侧 1px 分隔线，**永不自动折叠**
- 顶部：产品图标 48px 高，下方 1px 分隔线
- 条目高 **44px**，图标 19px，居中，无文字
- 当前页：图标与背景用强调色浅底，**左侧 2px 强调色竖条**贴边
- hover 显示 tooltip（文字为页面名），延迟 400ms
- 分组顺序：控制台 / 文件 / 插件 / 服务器配置 / 实例设置 / 计划任务 —— 分隔线 —— 系统监控 / 数据库 / Java 环境 / 面板设置
- 底部：展开按钮 + 当前用户头像

### 3.3 展开态

底部的展开按钮把图标栏变成 **220px** 带文字版（图标 + 页面名，条目高 36px）。

- 这是**偏好，不是模式**：一次性选择，跨页面、跨会话持久化到 `localStorage: nav.expanded`
- 展开态下当前页高亮方式不变
- 展开 / 收起有 160ms 宽度过渡，页面内容跟随重排，不做位移动画

**不要做成"编辑模式"那样的复合开关。** 这个按钮只改变导航的呈现密度，不改变任何页面的内容或布局逻辑。

## 4. 文件页整体结构

```
┌──────┬──────────────┬───────────────────────────────┐
│ 图标 │  侧边栏        │           主区                 │
│ 栏   │  300px        │                               │
│ 56px │  ⌘B 可折叠     │  浏览态 = 当前目录详情列表       │
│      │               │  编辑态 = 编辑器（可分屏）        │
└──────┴──────────────┴───────────────────────────────┘
```

**核心规则：主区永远显示"你正在看的东西"，侧边栏永远显示"你在哪"。**

| 主区形态 | 触发 | 内容 |
|---|---|---|
| 浏览态 | 没有打开任何文件 | 当前目录的详情列表（§6） |
| 编辑态 | 至少打开 1 个文件 | 编辑器组（§7） |

形态切换**完全自动**，不提供任何开关。关闭最后一个标签 → 自动回到浏览态。

## 5. 侧边栏

### 5.1 容器

- 宽 **300px**，可拖拽，min 240 / max 480，宽度持久化
- `⌘/Ctrl + B` 折叠 / 展开
- **折叠态 = 40px 竖条**，只保留一个展开按钮（不放竖排文字，40px 下排不下）
- 折叠状态持久化；但见 §9 的自动折叠规则

### 5.2 头部（38px）

左：`资源管理器`（小号大写标签样式）
右：`新建`(+) / `刷新` / `⋯` / `折叠侧边栏`(⌘B) 四个图标按钮，28px 见方

### 5.3 面板切换（一行分段，24px 高）

`文件` / `搜索` / `最近`，默认 `文件`。

- **文件**：§5.4 的树
- **搜索**：当前实例内的全文搜索（文件名 + 内容），结果按文件分组、可展开看命中行，点击跳到对应行
- **最近**：最近编辑过的文件，最多 20 条，按实例存

三个面板各自保留自己的滚动位置。这是**面板内容切换**，不是模式——它不改变主区，也不改变一级导航。

### 5.4 文件树

**与 v1 不同：树里同时显示文件夹和文件。** v1 之所以只放文件夹，是因为当时树只有 216px，文件名大量截断；300px 下这个问题基本消失。

- 行高 **26px**，每层缩进 14px
- 同级内：文件夹在前按名称升序，文件在后按名称升序
- 文件夹有展开箭头（仅在确有子项时显示）；文件没有
- 图标 14px，按扩展名着色（沿用 v1 §6.2 的分类）
- 当前打开的文件：强调色浅底 + 强调色文字 + 加粗
- 已打开但非当前的文件：主文字色（与未打开的次级文字色区分）
- 名称超长 ellipsis，`title` 给全名
- 展开状态按实例持久化
- 右键菜单与主区列表的 `⋯` 菜单保持同一组项、同一顺序

**不要默认展开多层。** 只展开到当前目录所在的那条路径。

### 5.5 底部

实例配额一行：`实例配额 24.6 / 80 GB` + 进度条。折叠态下隐藏。

## 6. 主区 · 浏览态

这是 v2 最关键的一处改动：**目录列表从侧栏搬到主区**，因此宽度充足，v1 里"修改时间被截断"的问题从根上消失。

自上而下四条：

### 6.1 面包屑条（36px）

沿用 v1 §4 的全部规则（可点击分段、点空白转输入框、中间省略、根目录禁用返回）。位置从页面顶栏移到主区顶部——它描述的是主区内容，不是整个页面。

### 6.2 工具条（46px）

左：`当前目录` + chip `23 项 · 50.5 MB`
右：目录内筛选框（30px 高）、`上传`、`新建`、`⋯`

**上传 / 新建 / 刷新 在浏览态和编辑态、在任何折叠状态下都保持同一组、同一顺序、同一形态。**

### 6.3 表头（32px）+ 列表

列：`名称` / `大小`(右对齐 110px) / `修改时间`(190px) / 操作(76px，表头留空)

- 行高 **40px**
- 列头可点击排序，当前排序列显示 ▲▼
- 其余行为沿用 v1 §6.2 / §6.3 / §6.4 / §6.5

### 6.4 空主区

从未打开过文件、当前目录也为空时，主区显示空状态（沿用 v1 §6.5）。

## 7. 主区 · 编辑态

### 7.1 编辑器组

一个"组"= 标签栏 + 面包屑 + 正文 + 状态条，四件套。分屏时每组独立拥有这四件。

### 7.2 标签栏（38px）

- 标签：类型图标 + 文件名（等宽）+ 未保存圆点（警告色）+ 关闭 `×`
- 非激活标签的 `×` 仅在 hover 时显示
- 中键关闭；`⌘/Ctrl+W` 关闭当前
- 超宽横向滚动不换行；上限 12 个，超出按 LRU 关闭最早的**已保存**标签
- 右键：关闭 / 关闭其他 / 关闭右侧 / 复制路径 / 在树中定位
- 右侧固定：`配置历史` 文字链接、`分屏` 图标按钮、`⋯`

### 7.3 编辑器面包屑（28px）

`测试服 / plugins / Vulpecula / config.yml`，等宽小字，次级文字色，每段可点击。与 §6.1 的目录面包屑是两个东西：这条描述**当前标签的文件**，不随目录切换而变。

### 7.4 正文

沿用 v1 §7.2 全部内容（行号槽、改动行标记、还原此行、语法高亮、光标与滚动位置缓存）。行号槽宽度按组宽自适应：单组 52px，分屏时 46px。

### 7.5 组状态条（30px）

左：`YAML · UTF-8 · LF` + `N 行已改` chip（无改动时不显示）
右：`还原` / `保存`，无改动时禁用

行列号**不放在这里**，放到全局状态条（§8），避免分屏时两个组各显示一份光标位置。

右：`1 个文件未保存`（有未保存时用警告色）· 产品版本

## 9. 分屏

### 9.1 行为

- `分屏` 按钮是**两项菜单**：`左右分屏` / `上下分屏`，不是单一开关
- 上限 **2 组**（数据结构按 N 组设计，UI 先只开放 2）
- 组间 12px 间距，可拖拽调整比例，比例持久化
- 拖标签到另一组可移动文件；拖到空白区可开新组
- 关闭一组的最后一个标签 → 该组消失，剩余组占满
- `⌘/Ctrl + \` 左右分屏当前文件

### 9.2 上下分屏不是备胎

对比两份 YAML 时上下排列让行号和缩进天然对齐，比左右更好读，而且不吃宽度。它是一个平等的选项，不要做成"窄屏才有"。

## 10. `⌘P` 转到文件

放在全局顶栏右侧的输入框，或直接 `⌘/Ctrl + P` 唤起浮层。

- 对**当前实例的全部文件路径**做模糊匹配（子序列匹配，如 `vulp con` 命中 `plugins/Vulpecula/config.yml`）
- 结果行：文件名（匹配字符高亮）+ 次行灰色显示所在目录
- 排序：最近打开过的优先，然后按匹配得分
- `↑↓` 选择，`Enter` 打开并聚焦当前编辑器组，`⌘Enter` 在新的分屏组打开
- 空输入时显示"最近打开"前 10 条

**这是取代"展开整棵大树"的正解。** `world/region/` 下有几百个 `.mca`，`plugins/` 下每个插件十几个文件，靠展开树去找是最慢的路径。

## 11. 响应式与自动折叠

以**视口宽度**为准（不是列宽）：

| 断点 | 行为 |
|---|---|
| ≥ 1600px | 全展开。分屏时侧边栏保持展开 |
| 1360 – 1600px | 开启分屏时**自动折叠**侧边栏；关闭分屏后恢复 |
| < 1360px | 侧边栏默认折叠，用户手动展开则临时**浮在主区之上**（overlay），选中文件后自动收回 |
| < 1280px | 左右分屏禁用，分屏菜单只剩"上下分屏" |
| < 1024px | 图标栏保留；侧边栏改为全屏抽屉；分屏禁用 |

自动折叠不覆盖用户的显式选择：如果用户手动展开过侧边栏，在本次会话内不再自动折叠它（记一个 `sidebar.userPinned` 标记，关闭分屏时清除）。

**硬指标：任何断点下，单个编辑器组的代码可视宽度不得低于 620px**（约 82 个等宽字符，能放下 Paper / Spigot 默认配置里最长的注释行）。实现完后按这个值自查。

## 12. 快捷键

| 键 | 行为 |
|---|---|
| `⌘/Ctrl + P` | 转到文件 |
| `⌘/Ctrl + B` | 折叠 / 展开侧边栏 |
| `⌘/Ctrl + S` | 保存当前标签 |
| `⌘/Ctrl + W` | 关闭当前标签 |
| `⌘/Ctrl + \` | 左右分屏当前文件 |
| `⌘/Ctrl + F` | 焦点在编辑器 → 组内查找；否则 → 聚焦目录筛选 |
| `⌘/Ctrl + Shift + F` | 打开侧边栏的"搜索"面板 |
| `⌘/Ctrl + 1 / 2` | 聚焦第 1 / 2 个编辑器组 |
| `↑ ↓` / `Enter` | 主区列表内移动 / 打开 |
| `Backspace` | 主区列表内返回上级 |
| `Esc` | 关闭浮层 / 退出路径编辑 / 取消多选 |

`⋯` 菜单里提供一个"快捷键"弹窗列出全部。

## 13. 后端依赖

v1 §9 的三项继续有效（文件夹打包下载 / 外部变更推送 / 保存冲突检测），**新增第四项**：

4. **文件索引**（`⌘P` 和侧边栏搜索面板都依赖它）。需要一个接口能返回当前实例的全部文件路径，或支持递归列目录。
   - 如果实例文件数可能上万（`world/region` 很容易几千个 `.mca`），不要一次性全量拉到前端。优先要后端提供**服务端模糊匹配**接口：`GET /files/find?q=vulp+con&limit=50`
   - 如果后端只能给全量列表，前端在首次唤起 `⌘P` 时拉取并缓存，缓存随目录写操作失效；同时**默认排除** `world*/region`、`world*/entities`、`libraries`、`cache`、`versions` 这几类目录（提供一个"包含全部"的开关）
   - 两条都做不到 → `⌘P` 降级为"仅在最近打开过的文件里搜索"，并在 PR 里标注

## 15. 明确不在范围

- 配色主题、字体
- 「配置历史」页面本身的改造（只调整入口位置）
- 编辑器的 LSP / 配置项智能补全
- 文件权限编辑（chmod）
- 超过 2 组的分屏
- 侧边栏"搜索"面板的替换功能（本期只做搜索，不做批量替换）
